# Roadmap

## Done
- Cross-view engine: processes, modules, ports, preload.
- Diff engine that localises a mismatch to the userspace or kernel layer and
  maps it to MITRE ATT&CK.
- Recheck loop to suppress race-induced false positives.
- C data plane (`libcrossview.so`) with a stable ABI; only the public API is
  exported (`-fvisibility=hidden`).
- Python `ctypes` bindings + CLI; JSON report with a published schema.
- Tests: C unit/smoke tests under ASan+UBSan and valgrind; Python tests incl.
  live-report schema validation; GitHub Actions CI (gcc + clang zero-warning
  builds, sanitizers, valgrind, clang-tidy, ruff, pytest).

## In progress
### 1. eBPF behavioural sensor (`bpf/`)
libbpf + CO-RE program providing views that are much harder to fake than
`/proc` reads, plus the behavioural signal for the ML layer:
- `sys_enter` syscall counts per PID (feature vector for anomaly detection)
- `sched_process_exec` (execve) — catch processes that never appear in `/proc`
- `init_module` / `finit_module` — module loads, to pair with the module check
- `connect` — outbound connections, for reverse-shell behaviour
Streams events to user space over a ring buffer as JSONL, joined to a scan by
`boot_id`. A kernel task-list iterator here becomes an additional, independent
process view.

### 2. Isolation Forest anomaly model (`eval/model/`)
Unsupervised model over per-process, per-window features from the sensor.
Rationale: no labelled rootkit dataset is needed, and it ranks alerts so the
deterministic findings aren't drowned. Deterministic cross-view checks catch
*hiding*; the model catches *behaviour* and prioritises. The model never
overrides a deterministic finding.

### 3. Evaluation harness (`eval/`)
Scripted scenarios run in the VM against real research rootkits, producing a
results table **generated by code, not typed by hand**: detected? / which
view caught it / time-to-detect / false-positives-per-hour on a scripted
benign workload / CPU overhead % with the sensor on vs off / syscall-dispatch
mode. See `docs/RUN_ON_VM.md`.

### 4. Remaining views
- `proc_maps`: hash each process's libc text segment against on-disk libc to
  catch in-memory trampoline hooks that leave `self_symbols` unchanged.
- eBPF task-iterator process view (depends on #1).

## Later
- Memory-forensics cross-check (Volatility 3) as the hardest-to-fake view.
- A small daemon mode with periodic scans and alert de-duplication.
